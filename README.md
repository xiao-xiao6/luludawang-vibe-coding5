# 推币机 · Coin Pusher

一个纯前端、零依赖、可直接打开就玩的推币机小游戏。**2.5D 透视视角**的电玩城机台：
投币 → 币从空中落到倾斜台面 → 推板往复 → 币堆互撞 → 掉出前沿拿钱 → 升级机台 → 换台重生。

**打开方式**：双击 `index.html` 即可（不需要服务器、不需要构建、不联网）。

---

## 玩法

| 操作 | 说明 |
| --- | --- |
| 点击台面任意位置 | 在该横向位置投币（落点有瞄准提示） |
| `空格` | 在当前位置投币 |
| `A` | 开关自动投币机（需先购买） |
| `H` | 超频：花金币换 8 秒双倍产出 |
| `L` | 抽奖（需 5 张券） |
| `P` | 暂停 / 继续推板 |
| `Esc` | 关闭面板 |

- **推板**在台面上方往复运动，把币堆往出币口推。
- 币越过最前方的**出币口**（青色高亮线）→ 按面值结算收益。
- 币掉进左右两角的**黑色斜纹沟** → 直接丢币，不给钱。
- 台面近似水平，**只有推板能推动币**，所以挂机不会白拿钱（已实测：90 秒纯挂机收益 0）。
- **金币见底**时机台会自动赠送救济金（30 金币），也可以直接点 HUD 上的「领救济金」立刻领取。
- **暂停推板**时推板停住，台面上的币仍然继续求解，不会卡住也不会穿模。

### 两条惩罚线（失败机制）

之前的版本「只能枯燥地看着金额增多」—— 因为除了掉沟没有任何代价。现在台面本身会给压力：

| 机制 | 触发 | 代价 | 对策 |
| --- | --- | --- | --- |
| **拥堵** | 台面超过容量 **88%** | 推板越推越慢（满台 −24%） | 排风马达（每级 −34% 影响） |
| **爆仓** | 满台后还硬塞 10 次 | 前沿 2 枚币被挤进角沟 | 防爆护栏（每级少丢 1 枚） |
| **漏币连锁** | 6 秒内掉沟 3 次 | 角沟临时变宽 ×1.15，持续 6 秒 | 稳住落点，等它过期 |

这三条都是**渐进**的：先减速（可感知、可挽回），再真丢币。实测数据（`_test/penalty.js`）：

| 玩法 | 峰值拥堵 | 拥堵时长占比 | 爆仓 |
| --- | --- | --- | --- |
| 慢手 0.7 枚/秒 | 4% | 0% | 0 |
| 正常 2 枚/秒 | 26% | 44% | 0 |
| 快手 4 枚/秒 | 42% | 82% | 0 |
| 故意硬塞满台 | 100% | 100% | 110 次/4 分钟 |

也就是说：**推得越猛，压力越大**，而挂机完全不会触发（惩罚只由玩家自己的操作触发）。

### 风险玩法：限时订单 + 超频

**限时订单**：机台每 48 秒给一个订单提议，9 秒内决定接不接。
接了 → 达标拿重赏；没达标 → 罚金 + 机台**过热** 12 秒（推板 ×0.72）。
**不接 = 不算失败**，所以惩罚永远是玩家自己选的。

关键是目标是**自适应**的：按玩家最近 22 秒的真实产出（指数滑动平均）反推，
所以初始机台不会收到根本做不完的单，满配机台也不会收到随手就过的白送单。
`_test/_probe_order.js` 实测（热身 40 秒后接单）：

| 订单 | 初始机台目标 | 满配机台目标 | 达成率 |
| --- | --- | --- | --- |
| 急速推落 | 14 枚 | 160 枚 | 100% |
| 连击挑战 | 5 连击 | 26 连击 | 80~95% |
| 零失误 | 7 枚连击不掉沟 | 10 枚连击不掉沟 | 100% |
| 钻石订单 | **不派单**（产不出钻石） | 2 枚钻石币 | 73% |

钻石订单还有一道**可行性筛选**：只有「这段时间的期望钻石数 ≥ 1.5 枚」才会派给你。

**超频**：冷却好了玩家自己点，花 45 金币换 8 秒产出 ×2 + 推板 ×1.25，冷却 40 秒。
必须手动触发，所以自动化长跑测试永远不会误触它。

### 币种

| 币 | 面值 | 特殊 |
| --- | --- | --- |
| 铜币 | 1 | 基础 |
| 银币 | 3 | 较重，推起来更"实" |
| 金币 | 10 | 高价值（立着画，带脉冲光晕） |
| 钻石币 | 25 | 棱面钻石造型，掉落额外给 1 颗钻石 |
| 幸运币 | 2 | 掉落额外给 1 张抽奖券 |
| 宝箱 | — | 伪3D 宝箱，推落触发 **JACKPOT**：现金奖励 + 撒 41 枚币到场 |
| 金币塔 | — | 伪3D 金币塔，**比宝箱更稀有**，推落给更大一笔现金 + 撒 22 枚币 |

### 连击

连击是**滑动窗口计数**：统计最近 **0.9 秒**内推落的枚数，而不是"只要间隔不超时就越滚越大"的单调计数器。

| 窗口内推落 | 倍率 |
| --- | --- |
| 6 枚 | ×1.4 |
| 11 枚 | ×1.8 |
| 18 枚 | ×2.5 |
| 30 枚 | ×4.0 |

倍率是**爆发奖励**而不是常驻增益：0.9 秒内推落 30 枚（约 33 枚/秒）才拿得到 ×4，
稳态推币只能吃到 ×1.4 ~ ×1.8。连击徽章只在**跨档**时弹出，震屏也跟着档位走，
所以高倍率在表现上是"稀有事件"，不会满屏乱抖。

### 升级

**金币升级**（10 项）：推板马达、行程连杆、滑板涂层、侧护栏、投币口、自动投币机、幸运石、扩容槽、
**排风马达**（拥堵对策）、**防爆护栏**（爆仓对策）。

**钻石升级**（2 项）：

- **磁力线圈**：在物理求解器内部对前沿的币施加真实横向力，把快要掉沟的币往中心带。
- **暴击芯片**：每枚推落的币有 **10% / 级**概率触发暴击 ×2（满级 30%），期望收益 +10% / 级。

所有升级都映射到真实仿真参数（速度 / 行程 / 摩擦 / 沟宽 / 容量 / 投币数 / 补给权重 / 自动频率 /
拥堵系数 / 爆仓损失），玩家能"感觉到"升级，而不只是看到数字变大。

### 换机台（Prestige）

累计收益达到门槛后可以**换机台**：清空全部升级与钻石升级，随机换一台带修饰的新机台，
并获得**永久收益加成**（每层 +20%）。

| 机台 | 修饰 |
| --- | --- |
| 标准机台 | 没有任何额外修正，最稳的一台 |
| 贪心机台 | 角沟宽 25%，但所有收益 +20% |
| 温柔机台 | 角沟收窄 25%，但所有收益 -10% |
| 富矿机台 | 机台补给好币更多（幸运 +2），推板慢 10% |
| 涡轮机台 | 推板快 18%，但台面摩擦略大 |

### 概率公开

「统计与玩法」面板里直接读代码里的同一张表，公示的概率和实现永远是同一个：

- **抽奖**（5 张券 / 次）：金币 +120~420 **32%** / 钻石 +1~3 **24%** / 金币雨 ×最多 10 **20%** /
  钻石雨 ×最多 5 **15%** / JACKPOT **9%**
- **连击判定**：0.9 秒窗口内推落 6/11/18/30 枚 → ×1.4/1.8/2.5/4.0
- **暴击芯片**：每级 +10% 概率触发 ×2
- **宝箱出现率**：每次补给按当前幸运等级实时计算（基础 1% + 幸运加成，上限 2.5%），冷却 60 秒
- **金币塔出现率**：基础 0.12% + 幸运加成（上限 1.2%），冷却 120 秒
- **拥堵**：容量 88% 起推板减速，满台 −24%
- **爆仓**：满台硬塞 10 次，挤掉 2 枚（防爆护栏每级少 1 枚）
- **漏币连锁**：6 秒内掉沟 3 次 → 角沟 ×1.15，持续 6 秒
- **限时订单**：首次 14 秒，之后每 48 秒提议一次，9 秒内决定；失败罚金 = 赏金 ×45% + 过热 12 秒
- **超频**：45 金币 → 8 秒产出 ×2 + 推板 ×1.25，冷却 40 秒
- **机台维护费**：每 6 秒扣一次，额度 = 1 + 0.5 × 升级总级数 + 2 × 换台层数（单次上限 60 ◎）
- **机台抽成**：每笔推落收益（含宝箱 / 金币塔赏金）抽走 **40%**
- **稀有币涓流**：每 5 秒检查一次，钻石 / 幸运 / 宝箱 / 金币塔的台面存量低于容量 2%
  （兼底 3 枚，幸运石每级 +0.5）就补一枚，超过容量 10% 停止 —— 稀有币永远有来源，又不会堆成印钞机

**台面满时的抽奖与 Jackpot 不会空放**：撒不下去的币会按面值折算成金币补偿给玩家，
日志里会写明"台面已满，折算 +N 金币"。抽到的奖励不会凭空蒸发。

### 平衡实测结果

固定随机种子，先预热 120 秒排空初始赠币，再测 90 秒稳态：

| 机台状态 | 投入 | 产出 | 比值 |
| --- | --- | --- | --- |
| 初始 | 208 ◎ | 262 ◎ | **1.26** |
| 中期（部分升级） | 624 ◎ | 1089 ◎ | **1.75** |
| 满配 | 1040 ◎ | 2271 ◎ | **2.18** |
| 满配 + 暴击 Lv3（同种子对照） | 1040 ◎ | 2848 ◎ | **2.74**（+26%） |

曲线是"起步略亏 → 升级后转正 → 满配效率高但仍有上限"，不会指数膨胀。
暴击芯片的边际收益是 **+26%**，和其它升级处在同一量级，不再是一枝独秀的断层最优解。

表里的产出是**抽成之后的净收益**（维护费走 `totals.upkeep`，不计入投入），
所以这张表本身就是「惩罚机制真的在扣钱」的回归断言：
维护费随升级总级数线性上涨，抽成随产出同步放大 —— 收益越高，被切走的越多。

> 历史对照：改造前初始机台 **0.88**（略亏）、满配 **3.89**、满配 + 暴击 **4.93**。
> 那时的「惩罚」全是软惩罚（拥堵减速 / 爆仓丢 2 枚 / 漏币把角沟变宽），
> 没有任何一项从钱包里扣钱，所以收益永远净流入、滚雪球停不下来。

上面的测量不碰超频（手动技能）且稳态不堆到拥堵阈值，所以这张表测的是**纯经营**：
投入产出比完全由「维护费 + 抽成 + 稀有币供给」决定，不受玩家操作波动干扰。

### 可复现性

所有随机都走**可播种 RNG**（`data.js` 的 `makeRng`，mulberry32），并且分成两条独立通道：

- `world.rng` —— 物理与掉落，决定仿真轨迹
- `rollRng` —— 暴击等结算随机

同一份种子跑两次，结果**完全一致**（自检里有这条断言）。所以平衡测试是真正的回归门禁，
而不是"每次跑都重新抽一次样"。两条流分开之后，暴击不会扰动物理轨迹，
"满配 vs 满配+暴击"的差异就只剩暴击本身，测出来的数字才干净。

## 双端适配

桌面端和手机端不是两套代码，而是**同一套判定**（`js/layout.js`，纯函数、零 DOM、可 headless 自检）：
按视口分出 4 档，再由 CSS 变量与 `body[data-mode]` 落地，避免「电脑正常、手机炸布局」。

| 档位 | 触发条件 | 布局 | 台面（典型） |
| --- | --- | --- | --- |
| `wide` | 宽度 ≥ 861 | 机柜 + 日志右列 | 1920×1080 → 480×580 |
| `stack` | 平板竖屏 / 中等宽度 | 单列，日志折到机柜下方 | 820×1180 → 576×696 |
| `narrow` | 宽度 ≤ 480 | 单列 + 操作区两行 + 大按钮 | 390×844 → 346×418 |
| `compact` | 横屏且高度 ≤ 560 | 台面在左、HUD 与操作在右 | 844×390 → 270×326 |

要点：

- **宽高比恒定**：台面永远 480:580，先按宽度铺满、再按可用高度回收，宁可变小也不变形。
- **安全区只扣一次**：`env(safe-area-inset-*)` 用隐藏探针实测，写进 `--safe-*` 变量，
  由 JS 从可用宽高里扣一次、CSS 负责把内容摆进安全区内。同一份刘海空间不会被算两遍，
  刘海屏上台面能拿到真实的可用空间。
- **触控**：`touch-action:none` 防止拖台面时页面跟着滚；`pointer:coarse` 下按钮一律 ≥44px、
  投币键 ≥52px；手机端提示语自动换成「点台面投币 · 拖动可瞄准」。
- **高清与性能**：DPR 上限统一由适配层决定（低端机压到 1.5、桌面 2），档位变化时自动重烘焙
  币精灵与静态台面；内存 ≤2G 或核心 ≤3 自动降粒子、桌面保留全特效。
- **手机横屏**：台面在左、HUD 与操作在右，纵向空间全给台面；横向放不下日志时自动收起日志列，
  超矮横屏再砍掉状态条保按钮。

## 技术要点

### 2.5D 视角（为什么不用 three.js）

台面在视觉上是**倾斜的**，但物理内核仍然是**干净的俯视 2D**。两者之间只隔一层 `js/project.js`：

```
projectX(x, y) = W/2 + (x - W/2) · k(y)      // 越远越向中轴收窄
projectY(y, z) = y - z · LIFT                // 离台越高越往上抬
scaleAt(y, z)  = k(y) · (1 + z · ZOOM)       // 越近/越高画得越大
```

k(y) 从远端的 0.68 线性过渡到近端的 1.00，所以护栏会向远处收剑、推板往前推时会"变大"。

**为什么不用 three.js**：

1. 投影是一次**解析变换**（上面三个式子），不是真三维几何 —— 引入整套 3D 管线不会多出任何表现力；
2. `project.js` 是零 DOM 的纯函数，所以透视数学**可以在 node 里断言**（单调性、无 NaN、影子随高度衰减），
   three.js 做不到这一点；
3. 物理仍然是俯视 2D，所以经济平衡测试的数字**完全不受视角影响** —— 换视角不会让回归门禁失效；
4. 零依赖是这个项目的立身之本（双击即玩、不联网）。

**离台高度 z** 是纯视觉量：币从上方落下、会弹跳、落地扬尘，但 z **不参与任何碰撞与结算**，
所以物理内核没有被污染。空中币暂时退出币与币求解 —— 所以"投下来砸进币堆"是真的会推开别的币。

**点击命中要反投影**：屏幕 x 不能直接当台面 x 用（同一屏幕 x 在不同深度对应不同台面 x）。
所以点击时按落点那一行反解算：`boardX = W/2 + (screenX - W/2) / k(dropZone.yMid)`。

### 渲染与性能

- **物理**：自研固定步长冲量求解器（120Hz），币-币用均匀网格做粗筛，
  推板是**硬约束**（币永远不会陷进去），共 10 次迭代。磁力线圈与推板一样，
  在积分阶段施加真实力，不做事后坐标修正。
- **渲染**：币精灵与**整张静态台面**（网格 / 收剑护栏 / 角沟 / 出币口 / PAYOUT 标签）
  全部预烘焙成离屏 canvas，主循环只做 `drawImage` + 梯形路径填充 ——
  不再每帧重建渐变、也不再每帧跑 `shadowBlur`（推板辉光改用几层半透明梯形伪造）。
  币按 art 分派四种精灵：圆片 / 棱面钻石 / 伪3D 宝箱 / 伪3D 金币塔；
  稀有奖励走"立着"的画法 + 烘焙好的脉冲光晕，不再和普通币一样只是转圈。
  绘制顺序用的排序缓冲也会复用，不每帧分配新数组。
- **音效**：全部用 WebAudio **程序化合成**（振荡器 + 噪声 + 带通滤波），零音频文件。
  连击音高按对数阶梯上行（1→0, 2→2, 4→4, 8→6, 16→8, 32→10, 64+→11 个半音），
  高连击也能听出区别，不会一过阈值就永远是最高音。
  音效开关只有一个真源 `soundOn`，按钮状态、`aria-pressed`、静音判定全部读它；
  切走标签页只挂起音频上下文、不改开关，切回来音效还在。
- **存档**：`localStorage`，每 10 秒 + 页面隐藏 + 关闭时落盘。
  存档上限**跟随台面容量**（扩容槽升到多少就存多少，不会读档丢币）；
  `fromJSON` 对每个字段做类型与范围校验，非法值回落默认或夹紧。
  惩罚 / 订单 / 超频的统计一并入库；进行中的订单与过热**不写进存档**（读档不会带着旧订单回来）。
- **无障碍**：弹窗有焦点陷阱与焦点还原、面板打开时屏蔽游戏快捷键、
  事件日志只增量追加新条目（读屏器不会反复播报整张列表）、
  `prefers-reduced-motion` 下关闭全部动画（含新增的 chip 脉冲与订单条）。
- **面板**：商店购买只更新受影响的那张卡片，滚动位置不跳、键盘焦点不丢。
